# Tauri, tao and wry, mined — 2026-09-07

- Research report, 2026-09-07. Corpus: `tauri-apps/tauri` at `1054107`, `tauri-apps/tao` at `27fe28c`,
  `tauri-apps/wry` at `c2a50d0` (shallow, blob-filtered clones, 2026-09-07), plus all three issue trackers and
  the `single-instance` plugin in `tauri-apps/plugins-workspace`. Reaction (`+n`) and comment (`cN`) counts are
  the API values on that date, taken over 40 search terms per repository, 1,418 distinct issues.
- **Where Tauri does NOT overlap with us — read this before anything below.** Tauri renders HTML in
  **WebKitGTK**, a browser engine we do not have and do not want, and its windowing layer **tao** is a GTK3
  wrapper. ADR-0001 rejects a widget toolkit by construction: we own the `wl_surface`, the frame loop, the
  keymap, the text stack and every pixel. That makes three whole categories of this corpus reference-only:
  - **Everything GTK mediates** — decorations, IME, DPI, clipboard, drag-and-drop, cursors, menus. tao's
    behaviour here is not our behaviour; what transfers is the *shape of the failure*, because GTK is reaching
    for the same Wayland protocols we reach for directly, and the compositor's answer is the same. Where a tao
    bug is really a GTK bug it is marked as such and dropped.
  - **Everything WebKitGTK does** — compositing modes, `WEBKIT_DISABLE_COMPOSITING_MODE`, DMA-BUF import,
    transparency, custom protocol handlers, WebRTC, cookies, the DOM. We have no web engine; none of it is a
    failure we can inherit. [tauri#14963](https://github.com/tauri-apps/tauri/issues/14963) (+239, c72, "bundle
    a Chromium renderer") and [tauri#9662](https://github.com/tauri-apps/tauri/issues/9662) (+150, c93, the
    WebKitGTK package vanishing from Ubuntu 24) are the two largest issues in the tracker and neither is ours.
  - **Everything Rust** — cargo, crates, the plugin ACL system, `zbus` versus `dbus`. Mechanism only.
  What *is* ours, and is why this pass exists: **Tauri ships**. It has produced hundreds of thousands of
  installed Linux desktop applications, so its tracker is the only corpus in this research programme that
  contains the failures of *distribution* rather than of rendering — `.desktop` files, icon themes, glibc
  floors, AppImage payloads, single instance, deep links, updaters, install prefixes. Zed does not package
  itself the way an application developer must; React Native's desktop ports target store-based installers.
  This is the gap.
- **Dedupe.** Every candidate was grepped against the title and body of all 282 issues in this repository
  (`gh issue list --state all --limit 800 --json number,title,body`, which returned the whole tracker), and the
  bodies of #23, #25, #51, #60, #63, #87, #89, #90, #106, #170, #175, #176, #209, #327, #329, #336 were read in
  full. The Zed-derived issues #327–#349 were checked individually; section D names every one that already owns
  a candidate. Every section E entry carries a `DEDUPE` line. The tracker was re-read immediately before filing
  (171 open issues, highest number #350) because an Electron pass is filing in parallel; no collision was found.
- **Result:** 10 sub-issues proposed and filed (section E), 24 candidates dropped (section D).
- **Collision, recorded after filing.** The Electron pass filed #366-#379 within minutes of this batch, and two
  pairs turned out to be the same issue: **#356 and #366** (the application identity and its desktop entry) and
  **#363 and #377** (a second launch hands over its arguments and its activation token). Both agents re-read the

## A. What Tauri does that we can copy as an approach

Each entry: the mechanism and where it lives, why it applies to a Skia/Wayland application that has to be
*installed*, and where it lands in our tree.

### A1. The desktop entry is a five-line template, and `StartupWMClass` is the whole point of it

- **Mechanism.** `crates/tauri-bundler/src/bundle/linux/freedesktop/main.desktop` is a Handlebars template with
  `Categories`, `Comment`, `Exec`, `StartupWMClass`, `Icon`, `Name`, `Terminal=false`, `Type=Application` and an
  optional `MimeType`. `generate_desktop_file` (`freedesktop/mod.rs`) renders it into
  `usr/share/applications/<product>.desktop`, builds `MimeType` by concatenating the declared file associations'
  MIME types with `x-scheme-handler/<scheme>` for every declared deep-link scheme, and quotes `Exec` when the
  binary name contains a space. `StartupWMClass` is set to the same value as `Exec`.
- **Why it applies.** On Wayland a client cannot set its own icon and cannot set the name a switcher shows.
  Both come from the installed entry, which the compositor matches to the surface through
  `xdg_toplevel.set_app_id` ⇔ `StartupWMClass`. Without the file, the flagship is a nameless grey square in the
  GNOME overview and nothing we do inside the process changes that. #329 already requires `set_app_id` to equal
  the installed entry's name; nothing in our tree installs one.
- **Lands in.** `packages/cli` (a package-time generator), consumed by #25's `PKGBUILD`; asserted against
  `WaylandWindow.cpp`'s `set_app_id`.

### A2. The icon tree is read from the images, not from their filenames

- **Mechanism.** `list_icon_files` (`freedesktop/mod.rs`) opens each source icon with a decoder, reads its real
  `dimensions()`, and places it at `usr/share/icons/hicolor/<w>x<h>[@2]/apps/<binary>.png` — a `BTreeMap` keyed
  by `Icon { width, height, is_high_density, path }` so duplicates collapse. The AppImage path then selects
  `icons.iter().filter(|i| i.width == i.height).max_by_key(|i| i.width)` for `.DirIcon`. Separately,
  `tauri icon` (`crates/tauri-cli/src/icon.rs`, 32 KB) takes **one** square source — SVG rasterised through
  `usvg`, or a PNG file — and generates the whole set for every platform, with an explicit `Fit` policy
  (`enum Fit`, CSS `object-fit`-shaped) for a non-square source and a Lanczos `resize_exact`.
- **Why it applies.** The icon-theme specification is a lookup by size and theme, so an icon at the wrong
  advertised size is invisible rather than wrong. One square source in, a deterministic tree out, is the only
  version of this that a test can assert.
- **Lands in.** `packages/cli` alongside A1.

### A3. Two package formats, one `data` tree, and `md5sums` as the manifest

- **Mechanism.** `crates/tauri-bundler/src/bundle/linux/debian.rs` builds `data/usr/{bin,lib,share}`, generates
  the control file, generates `md5sums` by walking the data tree, tars each with
  `HeaderMode::Deterministic`, and `ar`-archives `debian-binary` + `control.tar.gz` + `data.tar.gz`. The
  AppImage path (`appimage/linuxdeploy.rs`) does not re-derive any of that: it calls `debian::generate_data`
  and copies `data/usr/` into the `AppDir`. Resources land in `usr/lib/<product name>`, the changelog is gzipped
  into `usr/share/doc/<product>/changelog.gz`.
- **Why it applies.** One layout function with two consumers is the correct amount of abstraction, and
  `HeaderMode::Deterministic` is why two builds of the same tree produce the same archive — which is what makes
  a packaging artifact diffable in review. It also shows where the layout goes wrong: Tauri's own rpm path
  *does* re-derive it, and [tauri#11993](https://github.com/tauri-apps/tauri/issues/11993) is resources landing
  somewhere else.
- **Lands in.** `packages/cli`, and the resolver of E6 that has to find `usr/lib/<name>` at runtime.

### A4. The app category is a table, and the flagship's row already exists

- **Mechanism.** `crates/tauri-bundler/src/bundle/category.rs` is an `AppCategory` enum with a fuzzy
  `FromStr` (`CONFIDENCE_THRESHOLD = 0.8`, suggesting the nearest match on a typo) and one method per platform:
  `freedesktop_categories()` returns `"Game;LogicGame;"` for `PuzzleGame`, `"Development;"` for `DeveloperTool`,
  and so on for forty variants.
- **Why it applies.** `Categories=` is a closed vocabulary from the menu specification; a free-text field there
  produces an entry that validates and then never appears in a category. Suuudokuuu is `PuzzleGame`, which is
  the row that already exists.
- **Lands in.** `packages/cli`, as data next to A1.

### A5. Single instance is a D-Bus well-known name, and the bus decides the race

- **Mechanism.** `plugins/single-instance/src/platform_impl/linux.rs` (`tauri-apps/plugins-workspace`) requests
  `<bundle identifier>.SingleInstance` — optionally suffixed with a semver-compatibility string so two major
  versions do not collide — at object path `/` + the same name with `.` and `-` replaced, with
  `replace_existing_names(false)` and `allow_name_replacements(false)`. Acquiring the name means this process is
  the instance. `zbus::Error::NameTaken` means it calls `ExecuteCallback(argv, cwd)` on the existing owner and
  exits.
- **Why it applies.** There is no stale state to clean up after a crash — the bus drops the name with the
  connection — and the arbitration channel is the same object that decided the arbitration. `cwd` travels with
  `argv` because the second process's relative paths mean nothing to the first. This is the mechanism for both
  "launched twice" and "a URL arrived", which are the same event on a Linux desktop.
- **Lands in.** A new module in `packages/core/src` beside the D-Bus work of #274 and #326, surfaced through
  `Linking`.

### A6. Drag-and-drop is a three-state controller, because *leave* arrives before *drop*

- **Mechanism.** `wry/src/webkitgtk/drag_drop.rs`: `enum DragControllerState { Entered, Leaving, Left }` plus the
  last motion position and the pending path list. On leave the controller moves to `Leaving` and posts a deferred
  callback that commits to `Left` and fires the public `Leave` event **only if a drop has not arrived in the
  meantime**. `Drop` is accepted only from `Leaving`, and only when paths were already received. The position is
  stored on every motion so `Enter` can report where the drag actually is rather than `(0, 0)`.
- **Why it applies.** `wl_data_device` has the same ordering hazard between `leave` and `drop`, and the naive
  handler reports a cancellation on every successful drop —
  [tauri#14134](https://github.com/tauri-apps/tauri/issues/14134) and
  [tauri#10126](https://github.com/tauri-apps/tauri/issues/10126) are both sides of getting it wrong. #60
  explicitly deferred drag-and-drop as "a multi-year API design problem"; this is the design, in forty lines.
- **Lands in.** `packages/core/src`, sharing #60's `wl_data_device` objects.
- **Do not copy** `path_buf_from_uri` in the same file: it strips a literal `file://` prefix, so
  `file://localhost/tmp/x` becomes the path `localhost/tmp/x`.

### A7. The benchmark is five numbers about the artifact, and they live in another repository

- **Mechanism.** `.github/workflows/bench.yml` + `bench/src/run_benchmark.rs`, on every push to the default
  branch, under `xvfb-run --auto-servernum`, over three fixture applications of increasing weight
  (`helloworld`, `files_transfer`, `cpu_intensive`): binary size **and per-rlib size**; peak resident memory via
  `memory_profiler`; cold-start wall time via `hyperfine`; thread count and total syscall count from a single
  `strace -c` run (counting `clone`/`clone3` for threads); and dependency count. Results are pushed to
  `tauri-apps/benchmark_results` and rendered over time rather than compared with the previous commit, and the
  job prints `/proc/cpuinfo` and `/proc/meminfo` so a number has a machine attached to it.
- **Why it applies.** ADR-0001's whole argument against shipping a browser is about size, start-up and memory,
  and #20, #106, #124 and #126 all measure a frame that is already on screen. `strace -c` in particular is the
  cheapest possible "did we start spawning a thread per frame" alarm and needs no product instrumentation.
- **Lands in.** `packages/test-harness`, as a `bench:package` lane beside the compositor rig of #33 and #349.

### A8. The bundle configuration is a typed struct with a generated schema, and drift fails CI

- **Mechanism.** `crates/tauri-utils/src/config.rs` types every bundle field — `desktop_template`,
  `deep_link_protocols`, `file_associations`, `deb.depends/recommends/provides/conflicts/replaces`,
  `deb.{pre,post}_{install,remove}_script`, `appimage.bundle_media_framework`, `category` — and
  `.github/workflows/check-generated-files.yml` fails when the checked-in JSON schema drifts from the struct.
- **Why it applies.** Six artefacts have to agree on what the application is called (executable, entry, `app_id`,
  D-Bus name, package name, filenames), and Tauri's own failure is that they do not: `productName` is normalised
  to kebab case in two different files with two different rules, which is
  [tauri#14175](https://github.com/tauri-apps/tauri/issues/14175),
  [tauri#14231](https://github.com/tauri-apps/tauri/issues/14231) and
  [tauri#12073](https://github.com/tauri-apps/tauri/issues/12073).
- **Lands in.** `packages/cli`, read from the React Native application's own `app.json` under a `linux` key so
  there is no second manifest.

### A9. The updater's Linux support is one format, and the source says so

- **Mechanism.** `crates/tauri-bundler/src/bundle/updater_bundle.rs`, `bundle_update_linux`: filter the produced
  bundles for `PackageType::AppImage`, tar the one found, and return `Err(UnableToFindProject)` if there is none.
  The comment is the policy — *"right now in linux we hot replace the bin and request a restart, no assets are
  replaced"*.
- **Why it applies.** A `.deb` or an AUR install cannot self-update, because the files belong to the package
  manager. `expo-updates` is on ADR-0001's M4 dependency list, and the honest split — decline binary
  replacement, allow a signed JavaScript bundle in `$XDG_DATA_HOME` — has to be decided before the module is
  ported.
- **Lands in.** The support matrix of #87 and, if bundle updates are accepted, `packages/virtual-modules`.

### A10. `hit_test` is a nine-region bitmask, and it is a pure function

- **Mechanism.** `tao/src/window.rs:1666`: four bit constants, four comparisons against the border inset, one
  `match` over the eight non-zero combinations returning a `ResizeDirection`. Thirty lines, no state, no
  platform. The Linux backend calls it from motion (to pick the cursor), from button press (to start
  `begin_resize_drag`) and from touch, each with `border = scale_factor * 5`.
- **Why it applies.** Under GNOME we draw the decorations (#329), so the resize gutter, its cursor and its
  `xdg_toplevel.resize` edge are ours. The bitmask formulation makes the whole thing testable without a
  compositor, which is exactly what #329's unit criterion needs.
- **Lands in.** `packages/core/src/WaylandWindow.cpp` and `packages/core/tests/`.
- **The bugs in tao's use of it are the test cases:** the border is `scale_factor * 5` physical pixels, which at
  a fractional scale is a sub-5-pixel target ([tauri#3040](https://github.com/tauri-apps/tauri/issues/3040)); the
  cursor is only updated on motion over a *decorated-false* window, so a hover shows the wrong cursor
  ([wry#399](https://github.com/tauri-apps/wry/issues/399)); and on Wayland the arithmetic uses
  `window.position()`, which is always `(0, 0)`.

### A11. Do not commit a buffer before the first configure — defer with a one-shot handler

- **Mechanism.** `tao/src/platform_impl/linux/window.rs:112`, comment: *"Trying to prevent Wayland Protocol Error
  about mismatched xdg_surface_buffer sizes"*. The window connects a `configure` handler that, on its first
  invocation, disconnects itself and only then applies `maximize()` and `set_resizable()`. The same file's
  `WindowMaximizeProcess` (`util.rs`) is a three-step idle-driven state machine for the same reason: set
  resizable, maximize, restore resizable.
- **Why it applies.** This is #337's failure from the other side of a toolkit, and evidence that the ordering is
  hard enough that GTK does not save you from it: [tao#977](https://github.com/tauri-apps/tao/issues/977) is
  protocol error 71 when restoring a maximized window, and
  [tauri#10702](https://github.com/tauri-apps/tauri/issues/10702) (+70, c56) is the same error class as the
  single most-reacted Linux bug in the tracker.
- **Lands in.** A note on #337 and #331; no new issue.

### A12. Every artifact-shaped test is an integration test that builds, runs and compares stdout

- **Mechanism.** `crates/tests/restart/tests/restart.rs`: compile the test binary, copy it to a temporary
  directory, invoke it through one symlink and then through a nested pair, and assert stdout equals the *real*
  path twice. The whole point is that `current_exe()` is not the answer, and the test is 125 lines with no
  framework.
- **Why it applies.** E6's resolver has exactly this hazard, and this is the exact test.
- **Lands in.** `packages/core/tests/`.

### A13. Degrade by naming the service, then continue — and the counter-example

- **Mechanism.** `tao/src/platform_impl/linux/portal.rs` reads `org.freedesktop.appearance color-scheme` from
  `org.freedesktop.portal.Settings` with a five-second timeout, subscribes to `SettingChanged`, and maps
  `1 => Dark, 2 => Light, _ => Light`, logging and continuing on every D-Bus error.
- **Why it applies.** It is the same portal, the same key and the same fallback shape as our #52, #260 and #326,
  independently arrived at — which is worth recording as corroboration rather than as new work.
- **The counter-example is in the next file.** `taskbar.rs` `dlopen`s `libunity.so.{4,6,9}`, asks Unity whether
  it is running, and returns silently when it is not — 161 lines that on every current desktop do nothing and
  tell nobody. Degrading loudly and degrading silently are one line apart; E10 exists so we choose once.

### A14. The e2e rig is an intermediary WebDriver node, and it is not in CI

- **Mechanism.** `crates/tauri-driver` (421 lines): a WebDriver intermediary that listens on `--port 4444`,
  spawns the platform's native driver (`WebKitWebDriver` on Linux, Edge Driver on Windows) on `--native-port
  4445`, and proxies. A client speaks W3C WebDriver and never learns which platform it is on.
- **Why it applies as a *shape*.** It is the same answer #7 and #214 reach for — an external driver speaking one
  protocol to an in-process endpoint — and the platform-selection layer is the transferable idea.
- **Why it is also a warning.** `grep -rl 'webdriver\|tauri-driver' .github/` returns nothing: the rig is not run
  in CI, on any platform. [tauri#6541](https://github.com/tauri-apps/tauri/issues/6541) (+6, c7) is
  `tauri-driver` failing on `.click()` and `.setValue()`, open. A driver nobody runs is a driver that does not
  work, which is #233's rule applied to the harness itself.

### A15. The AppImage's environment block is the entire failure surface, and it is checked in

- **Mechanism.** `crates/tauri-bundler/src/bundle/linux/appimage/linuxdeploy-plugin-gtk.sh` writes the `AppRun`
  environment: `GTK_DATA_PREFIX`, `GTK_PATH`, `GTK_IM_MODULE_FILE`, `GDK_PIXBUF_MODULE_FILE`,
  `GIO_EXTRA_MODULES`, `GSETTINGS_SCHEMA_DIR`, `XDG_DATA_DIRS` — and
  `export GDK_BACKEND="${GDK_BACKEND:-x11}" # Crash with Wayland backend on Wayland`.
- **Why it applies.** That one line moves every user of a Tauri AppImage onto XWayland to work around
  [tauri#8541](https://github.com/tauri-apps/tauri/issues/8541), and the `XDG_DATA_DIRS` line resets the user's
  cursor theme ([tauri#11023](https://github.com/tauri-apps/tauri/issues/11023)). The generalisable rule, which
  is E3's acceptance criterion whichever bundle format is chosen: **a launcher we ship exports no variable that
  selects a display backend, a driver, an ICD path, a font configuration or an input method**, and a portable
  bundle never carries the Vulkan loader, an ICD, Mesa, `libdrm`, `libwayland-client` or `libxkbcommon`.
- **Lands in.** A CI gate over published artifacts, in `packages/test-harness`.

## B. Tauri, tao and wry issues that describe a failure mode we will hit

Marked **[GTK]** or **[WebKit]** where the mechanism is a toolkit we do not use and only the *class* transfers,
and **[ours]** where the failure is at the Wayland or the packaging layer and would be ours verbatim.

## C. Test shapes worth porting, and what tao and wry do not test

### C1. tao has no functional tests at all, and that is the finding

`tao/tests/` contains three files and every one of them is a compile-time marker assertion:
`send_objects.rs` checks that `EventLoopProxy`, `Window` and the identifier types are `Send`;
`serde_objects.rs` checks that the event and keyboard types implement `Serialize`/`Deserialize`;
`sync_object.rs` checks one `Sync` bound. There is not a single test of window creation, decoration
negotiation, the keymap, the DPI arithmetic, `hit_test`, or the event loop — in 3,700 lines of Linux backend.
`.github/workflows/ci.yml` is a build matrix: five targets × three feature sets, `cargo test` on the three that
can run it, which for the Linux target means running those marker assertions. **wry has no `tests/` directory at
all.**

This is the react-native-macos lesson from #209 in a second corpus: the surface exists, the CI is green, and the
green means it compiles. It is also the explanation for section B — every failure there is in code no test
touches. Our #211/#227/#230 drift oracles and the 100 % gate exist precisely to not be here.

### C2. `hit_test` is the shape of an assertion that needs no compositor

Thirty lines, four bit constants, nine outcomes, no state, no platform types (`tao/src/window.rs:1666`). It is
called from three different event handlers with three different coordinate sources, and if any of those
disagrees, only one of the three is wrong. Extracting the geometry decision as a pure function with a table test
over all nine regions plus the four corners at the exact boundary — and separately asserting each call site
converts into that space correctly — is the whole test design for #329's resize gutter. tao has the function and
none of the tests.

### C3. Assert `current_exe()` through symlinks, by building and running

`crates/tests/restart/tests/restart.rs` (125 lines): compile the binary, copy it to a temporary directory,
invoke it through one symlink and through nested symlinks, and assert stdout is the resolved real path both
times. It is a single `#[test]` — deliberately, with a comment explaining that splitting it would make cargo
wait on itself. E6's resolver has exactly this hazard and this is exactly the test.

### C4. Five artifact numbers, three fixtures, one `strace -c`

Section A7. The shape worth copying is the parsing discipline: `parse_strace_output` turns the `-c` summary into
a map, threads are `clone` + `clone3`, syscalls are the `total` row — so the assertion is over a parsed
structure, not over a log line. Three fixtures of increasing weight mean a regression can be localised to
"only the heavy one", and per-rlib sizes mean it can be localised to a component. Results in a separate
repository, rendered over time, is the gospel's "numbers are tracked, not vibed" with an implementation.

### C5. Two feature axes × five targets, with `--no-default-features` as a first-class row

`.github/workflows/test-core.yml` runs every target with `{--no-default-features, --all-features}`, and downgrades
`test` to `check` for the `no-default` row rather than dropping it. `tao`'s `ci.yml` does the same over three
feature sets. The transferable rule: the minimal configuration must at least compile in CI, every time, or the
optional-dependency graph rots. We have CMake options and no such row.

### C6. The generated-file drift gate

`.github/workflows/check-generated-files.yml` fails when the checked-in JSON schema does not match the one
regenerated from the Rust types. It is the same mechanism as our codegen determinism gate (#85), applied to
configuration rather than to bindings, and it is what makes A8's schema safe to depend on.

### C7. What Tauri tests that we should not bother copying

- The **ACL/capability test suite** (`crates/tests/acl`) is large and well-built and tests a permission system we
  do not have.
- The **app-updater integration test** is a signed-artifact round trip whose Linux half only covers AppImage —
  the one format E5 may well decline.
- The **`tauri-driver` WebDriver rig** is not run in CI on any platform (section A14) and its Linux back end is
  `WebKitWebDriver`, which drives a DOM. #7 and #214 already own our equivalent, and #233's rule — a scenario
  fails on a logged error by default — is what stops it decaying the same way.

## F. The ten highest-value picks

1. **#356 — the desktop entry, the icon tree and the `app_id` (E1).** It is the cheapest issue in the batch and
   three others depend on it: the tray, the taskbar signal and the deep link all resolve through the installed
   entry. Without it, every screenshot of the flagship is a nameless grey square, and #329's `set_app_id` has
   nothing to match.
2. **#357 — the runtime dependency floor (E2).** The failure is silent by construction: the package installs and
   the application dies on the user's machine. tauri#12883 is the same omission filed against the same missing
   check, and #25's "manual clean-system install test" is the only thing standing between us and it.
3. **#363 — single instance and deep links (E8).** Launching twice is a bug every desktop user finds in the first
   week, and #271's OAuth redirect cannot work without it — a dependency currently written down nowhere.
4. **#362 — one manifest, one identity (E7).** Four filed Tauri bugs are one missing schema, and it already has
   four concrete consumers in this batch, so it is not speculative generality.
5. **#361 — resource resolution (E6).** Every path in our runtime is relative to a build tree that will not
   exist. It is also the issue that makes #314's loud-font-failure rule survive being installed.
6. **#358 — the portable bundle decision (E3).** +122 reactions of demand against a documented pattern of
   breaking the graphics stack, and the never-bundle gate is worth having even if the answer is "neither".
7. **#359 — the artifact numbers (E4).** ADR-0001's central claim is about size, start-up and memory, and we
   measure none of them; the rig is a workflow file and three parsers.
8. **#364 — the drag-and-drop session (E9).** #60 explicitly deferred it as a multi-year design problem and wry
   has the design in forty lines. The `leave`-before-`drop` rule is one test that seven filed Tauri bugs would
   have failed.
9. **#360 — the update policy (E5).** `expo-updates` is on M4's dependency list, our channel is AUR, and Tauri's
   own answer — one bundle format, hot-replace the binary, no assets — is not available to us. Deciding after the
   port is deciding twice.
10. **#365 — four capability answers (E10).** It is P3 and it is on this list because tao's silent `libunity`
    block is what happens when nobody decides: 161 lines that do nothing and tell nobody, shipped for years.
